# Zip2Learn

ZIP ファイルや Ghidra の解析ファイル（`.gzf`）を**展開・実行せずに**読み取り、
**証拠付きの DFIR・静的解析の演習**を作る教育用ツールです。

1. **スキャン** — ZIP の中身を読み取り、ログ・資料・注意が必要なファイルに分けて示す
2. **教材化** — ログの 1 行 1 行を根拠に、段階ごとの設問と時系列をつくる
3. **学習** — 設問に答え、根拠のログへ飛んで確かめ、最終レポートで振り返る

すべての正解は、ログや解析結果のどの行から来たかをたどれます。

---

## 安全性

- **実行しない。** ZIP 内のプログラム・スクリプト・マクロは起動しません。
- **展開しない。** ZIP の中身はディスクに書き出さず、メモリ上で読みます。
- **外部へ送らない。** 処理はすべて手元で完結します。
- **手元だけで待ち受ける。** サーバーは `127.0.0.1` でのみ動きます。
- **パスワードを残さない。** 入力したパスワードは保存も記録もしません。

---

## 必要なもの

- Python 3.10 以降（追加のパッケージは不要）
- ブラウザ（Chrome または Safari）
- Docker（Ghidra の演習を作る場合だけ）

---

## 起動

```bash
python3 backend/api.py
```

表示された `http://127.0.0.1:<ポート>/` をブラウザで開きます。
ポートは起動のたびに変わります。終了は `Ctrl+C` です。

> `index.html` を直接開いたり、`python3 -m http.server` で配信したりすると動きません。

## 使い方

### ログから演習を作る

1. ホームの **「ZIPファイルの中身を調べる →」** を押す
2. ZIP が入っている**フォルダ**を選び、一覧から ZIP を開く
3. **「汎用解析で教材を作る」** を押す
   （暗号化されたログは、プロファイルを使ったときだけ **「同梱の案内を使って読み取る」** で読めます）
4. **「演習を開く」** → 段階ごとに証拠を読み、設問に答える
5. **「根拠ログを見る」** で、正解の根拠になった行を確かめる

### Ghidra ファイルから演習を作る

1. Docker を起動する
2. ホームの **「Ghidraファイルから演習を作る →」** を押す
3. 初回だけ **「処理環境を準備する」** を押す（約 570 MB をダウンロード）
4. `.gzf` を選んで **「演習を作成する」** を押す

まず試すときは **「同梱サンプル（termmines）で試す」** を押してください。
termmines は Ghidra の公式教材のマインスイーパーで、マルウェアではありません。

## 設問の種類と出題数

設問は「テンプレート」（設問の種類）ごとに、根拠を確かめられたものだけを候補として
作ります。そのうえで、1 回の演習に出す設問を**最大 8 問**選びます。候補が 8 問に
満たなければ、少ないまま出します（数を満たすために根拠の弱い設問は足しません）。

**ログ教材（ZIP）— 5 分類・14 種類**

| 分類 | 種類 |
|---|---|
| ログの読み取り | 起動したプログラム、起動を記録した端末、**起動時のコマンドライン**、操作されたファイル、ファイル操作を記録した端末、通信の要求元、**通信の宛先** |
| 根拠の特定 | 起動の根拠となる行、**ファイル操作（作成・書き込み）の根拠となる行**、通信の根拠となる行 |
| 記録の関連付け | 二つの記録の前後関係、**二つの記録の時間差（整数秒）** |
| ATT&CK との対応 | 記録が裏付ける手法 |
| 判断の限界 | 1 行の通信記録から言えること |

**Ghidra 静的解析教材（GZF）— 4 分類・7 種類**

| 分類 | 種類 |
|---|---|
| 文字列の参照 | 命令が参照する文字列、**文字列への参照命令を持つ関数（参照元）** |
| 直接呼び出し | 呼び出し命令の行き先、**関数の入口への直接呼び出し命令を持つ関数（呼び出し元）** |
| 外部関数 | 外部関数の見分け、**外部関数の登録先として保存されているライブラリ** |
| 判断の限界 | **命令の記録だけでは確認できないこと** |

太字は今回追加した種類です。

- **入力しだいで作られない種類があります。** たとえば、端末が 1 台だけなら「端末を
  読む」設問は作れません（誤答にできる別の端末が無いため）。二つの記録の時刻の
  細かさ（秒までか、ミリ秒までか）が違う、差が整数秒にならない、タイムゾーンの
  無い別々のログどうし、といった組では時間差の設問を作りません。外部関数の登録先は、
  ライブラリ名が 4 種類以上保存されていないと作りません（同梱サンプル termmines は
  登録先がすべて不明 `<EXTERNAL>` なので、この種類は出ません）。
- 抽出が上限で打ち切られた GZF では、正解が一つに決まらなくなる種類だけを作りません
  （文字列の参照・参照元は参照の一覧、呼び出し元は呼び出しの一覧、外部関数の見分けは
  関数と外部関数の一覧が完全である必要があります）。
- **選び方**: まず種類が重ならないように選び、分類ごとの数が偏らないようにし、同じ
  行・同じ命令について「値を読む設問」と「その行を根拠として選ぶ設問」のような
  逆向きの組をなるべく並べません。同じ入力・同じ版からは、同じ設問が同じ順で出ます。
- 作れなかった種類と理由、上限のために出さなかった設問は、別々に最終レポートの
  「断定できなかったこと」と教材データ（`selection`）に残ります。導入画面の設問数・
  所要時間の目安と、振り返りの得点の母数は、実際に出した設問から数えます。
- 教材には設問の種類の版（`generator.quizTemplates`）を記録します。保存済みの教材は
  起動時に作り直したり書き換えたりしません。新しい種類の設問を含めるには、元の ZIP・GZF
  から教材を作り直してください。作り直すと同じ ID の教材が置き換わります（学習の途中経過は
  もともと保存していないので、影響はありません）。種類の識別子（`templateId`）を持たない
  以前の教材も、そのまま表示・採点・振り返りできます。

**確認した環境（2026-09-28）**: macOS（Apple Silicon）の Python 3.14 と Node.js 26 で、
Docker と実ブラウザを使わない自動テスト（合成したログ・合成した抽出結果・同梱サンプルの
事前抽出データ）で確認しています。追加した種類の、実コンテナでの生成と Chrome・Safari
での操作は**まだ確認していません**。

## 対応範囲

- **ログの形式:** EDR ログ（端末の記録）とプロキシログ（Squid 形式）
  - プロキシログは、プロファイルで指定したときだけ使います
- **Ghidra:** 自動解析済みの `.gzf` ファイル
- ZIP の構造をあらかじめ登録したいときは、プロファイル（JSON）を用意して
  `DATASET_PROFILE_DIR=/path/to/profiles python3 backend/api.py` で起動します

新しいログ形式やプロファイルの追加方法は
[開発者ガイド](docs/データセット教材基盤_開発者ガイド.md)にあります。
